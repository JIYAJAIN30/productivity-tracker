# Contributing to Productivity Tracker

Thank you for considering contributing to Productivity Tracker.

We welcome contributions of all kinds including:

* Bug fixes
* Feature additions
* UI improvements
* Documentation improvements
* Performance optimizations
* Refactoring

---

# 📌 Before You Start

Please:

* Read the project [README](README.md) carefully
* Check existing issues before creating a new one
* Avoid duplicate pull requests
* Follow the existing code style

---

# 🚀 Getting Started

## 1. Fork the Repository

Click the **Fork** button on the top-right corner of the repository.

---

## 2. Clone Your Fork

```bash
git clone https://github.com/YOUR_USERNAME/productivity-tracker.git
```

---

## 3. Navigate to the Project Directory

```bash
cd productivity-tracker
```

---

## 4. Create a New Branch

Use meaningful branch names.

Examples:

```bash
git checkout -b feature/add-dark-mode
```

```bash
git checkout -b fix/timer-reset-bug
```

---

# 🛠️ Development Guidelines

## Code Style

Please:

* Write clean and readable code
* Use meaningful variable names
* Keep functions small and reusable
* Add comments where necessary
* Maintain consistent formatting

---

## UI Guidelines

* Keep the interface minimal and clean
* Maintain responsiveness
* Avoid unnecessary animations
* Ensure accessibility where possible

---

## JavaScript Guidelines

* Prefer ES6+ syntax
* Avoid global variable pollution
* Keep logic modular
* Reuse functions whenever possible

---

# ✅ Commit Message Guidelines

Write clear and professional commit messages.

Examples:

```bash
git commit -m "Add dark mode toggle"
```

```bash
git commit -m "Fix timer synchronization issue"
```

```bash
git commit -m "Improve mobile responsiveness"
```

---

# 📤 Submitting a Pull Request

Before submitting:

* Ensure your code works properly
* Test UI responsiveness
* Check for console errors
* Pull latest changes from upstream

Then:

1. Push your branch

```bash
git push origin your-branch-name
```

2. Open a Pull Request

3. Clearly explain:

* What changes you made
* Why the changes are needed
* Screenshots (if UI changes were made)

---

# 🐛 Reporting Bugs

When reporting bugs, include:

* Browser name/version
* Steps to reproduce
* Expected behavior
* Actual behavior
* Screenshots if applicable

---

# 💡 Suggesting Features

Feature suggestions are welcome.

Please describe:

* The problem your feature solves
* How the feature should work
* Any UI ideas/mockups if applicable

---

# 📌 Good First Issues

Beginner-friendly contributions may include:

* Adding animations
* Improving accessibility
* Optimizing JavaScript logic
* Updating documentation
* Adding keyboard shortcuts

---

# 📜 Code of Conduct

Please be respectful and professional.

We aim to maintain a welcoming and collaborative environment for everyone.
